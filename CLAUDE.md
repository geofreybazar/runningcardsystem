# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BFP-NCR Running Card System: for a fire location in Metro Manila it lists the nearest fire stations with an available truck, grouped into alarm levels, and lets the owning city's radio operator dispatch, raise the alarm, and close the incident. Full technical documentation: [docs/README.md](docs/README.md).

## Stack

- `frontend/`: React 19, Vite, Tailwind v4, shadcn/ui (JSX), React Router 7, `@vis.gl/react-google-maps` (Maps JS, Places API (New), Geocoding).
- `backend/`: NestJS 12 (ESM), Prisma 7 + `@prisma/adapter-pg`, PostgreSQL, `@nestjs/authentication` / `@nestjs/authorization` (0.1.x), Zod (via Nest's `StandardSchemaValidationPipe`), Vitest.

## Commands

Backend (`cd backend`): `npm run start:dev` · `npm run build` · `npm run lint` · `npm test` (unit) · `npm run test:e2e` (wipes the DB in `TEST_DATABASE_URL`; refuses unless its name ends in `_test`) · `npx prisma migrate dev --name <x>` then `npx prisma generate` (Prisma 7 doesn't auto-generate) · `npx prisma db seed` (re-runnable).
Single test file: `npx vitest run src/geo/city-locator.spec.ts` or `npx vitest run --config vitest.config.e2e.ts test/incidents.e2e-spec.ts`.

Frontend (`cd frontend`): `npm run dev` (proxies `/api` to `API_URL`, default `localhost:3000`) · `npm run build` · `npm run lint` · `npm test` · `npm run test:e2e` (Playwright in a browser; starts its own API on 3100 and **wipes the `_test` DB**).

CI: `.github/workflows/ci.yml` runs both apps' lint/test/build plus backend e2e (throwaway Postgres) on push to `main` and PRs, then its `deploy` job SSH-deploys green `main` pushes to the VPS (skipped until the `VPS_HOST` repo variable is set; see deployment.md#continuous-deployment); keep it in step when scripts change.

## Key architecture decisions

- **Deny-by-default authorization.** Every route needs `@Can(AccessPolicy, '<ability>')`, `@Can.Anyone()` or `@Public()`. Abilities live in `backend/src/auth/access.policy.ts`; record checks (`editCity`, `dispatchIn`) are done in services with `authz.authorize(...)`.
- **Offices drive access.** `User.officeLevel` REGIONAL/DISTRICT/CITY → `areaCityIds` and `dispatchCityId`, computed in `backend/src/auth/area.ts` and added to every request's user by `UserLoader`. Only Radio Operators of the fire's city (FD1/FD5 district offices count as their single city) and Super Admin dispatch. The frontend mirror is `frontend/src/utils/permissions.js` (+ `constants/office.js`); keep them in sync.
- **City of a point** comes from bundled barangay outlines (`CityDirectory.cityAt`), not from Google. The cache is per process; restart after re-seeding.
- **Tokens:** 15-min access JWT in memory on the client; rotating 7-day refresh token only in the httpOnly `rcs_rt` cookie (path `/api/auth`). The user is reloaded every request, so disabling an account takes effect immediately.
- **Running card** is computed per request from live truck status. Dispatch claims trucks with conditional updates in a transaction (one truck per station, never double-booked).
- **Special deployments** (ASEAN, SONA): Regional Operations sets trucks to `DEPLOYED`, which the running card and dispatch skip (they take `AVAILABLE` only). Only the deployment sets and clears `DEPLOYED`.
- **Soft deletes** for users, stations and trucks; incident history keeps references.

## Conventions

- Backend is ESM: relative imports end in `.js`; tests use Vitest. Check `backend/AGENTS.md` for Nest 12's first-party packages before adding a library (ignore its NestJS Observe section; Observe is not installed).
- Validate with Zod strict objects on `@Body/@Query({ schema })` (no class-validator). Rules a form also uses live in `backend/src/shared/validation.ts` (imports only zod; the frontend bundles it as `@shared/validation`). List fields explicitly in Prisma `data`. Audit user/station/truck/pin/settings changes via `AuditService.log()`.
- Frontend: `@/` alias; never hand-edit `src/components/ui/` (generated by `npx shadcn@latest add`, needs React 19); use theme tokens from `src/index.css`; call the API only through `service/<domain>.service.js` + a `hooks/<domain>/` query or mutation hook (pages stay thin, parts go in `components/features/<feature>/`; layout mirrors the FIIS project).
- Comment the *why*; mark deliberate limits as `shortcut: <limit>, <when to upgrade>`.
- Git: work on a feature branch; after it is merged into `main` (or its pull request is merged) and CI is green, delete it locally and on GitHub (`git branch -d <b> && git push origin --delete <b>`). See [docs/development/conventions.md](docs/development/conventions.md#git-workflow).

## Restrictions

- E2E tests drop the schema of the `TEST_DATABASE_URL` database (the user approved this). Never point it at a real database. Prisma blocks `migrate reset` for AI agents: ask the user first.
- Never commit `.env` files or keys. The Google key is a browser key and must stay referrer-restricted.
- `SEED_PLACEHOLDER_TRUCKS=true` is for demos and tests only.
- Docker stack tested 2026-11-07 (see [docs/development/deployment.md](docs/development/deployment.md)); re-test after changing the Dockerfiles, the seed's imports or nginx.
- VPS production = `docker-compose.yml` + `docker-compose.prod.yml` (Caddy HTTPS, secrets in root `.env`); tested locally 2026-11-08, re-test after changing it or `deploy/`.
- Open security items: [docs/security/gaps.md](docs/security/gaps.md).
